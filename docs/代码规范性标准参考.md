## 代码规范性标准参考

#### Google C++ Style Guide （谷歌主导的开源项目遵守指南）

[扉页 — Google 开源项目风格指南](https://zh-google-styleguide.readthedocs.io/en/latest/google-cpp-styleguide/)

目标：优化平均水平的软件工程师阅读、维护和调试代码的体验，而非编写代码的舒适度

具体内容总结：[Google C++ Style Guide](Google C++ Style Guide.md)

| 优先级 | 规范内容                          | 为什么重要                           | 推荐写法                            | 不推荐写法                   |
| ------ | --------------------------------- | ------------------------------------ | ----------------------------------- | ---------------------------- |
| ⭐⭐⭐⭐⭐  | **命名规范统一**                  | 可读性最重要。看到名字就知道含义。   | `class BinaryTree` `int node_count` | `class btree` `int a`        |
| ⭐⭐⭐⭐⭐  | **成员变量加 `_`**                | 快速区分类成员与局部变量，减少错误。 | `int size_;`                        | `int size;`                  |
| ⭐⭐⭐⭐⭐  | **禁止 `using namespace std;`**   | 避免命名冲突，符合工程规范。         | `std::vector<int>`                  | `using namespace std;`       |
| ⭐⭐⭐⭐⭐  | **类成员默认 private**            | 防止外部随意修改数据，体现封装思想。 | `private: vector<int> data_;`       | `public: vector<int> data;`  |
| ⭐⭐⭐⭐⭐  | **统一缩进与大括号风格**          | 提高代码阅读性，减少逻辑错误。       | `if (x) { ... }`                    | `if(x)...`                   |
| ⭐⭐⭐⭐⭐  | **函数职责单一**                  | 一个函数只做一件事，便于调试和维护。 | `InsertNode()` 只负责插入           | 一个函数同时插入+打印+排序   |
| ⭐⭐⭐⭐⭐  | **变量作用域最小化**              | 降低变量污染与误修改风险。           | `for (int i=0;...)`                 | `int i; ... for(i=0;...)`    |
| ⭐⭐⭐⭐   | **头文件使用 include guard**      | 防止头文件重复包含。                 | `#ifndef STACK_H_`                  | 无保护                       |
| ⭐⭐⭐⭐   | **`.h` 与 `.cc` 分离**            | 体现工程结构，便于大型项目维护。     | `stack.h` + `stack.cc`              | 所有代码写一个 cpp           |
| ⭐⭐⭐⭐   | **头文件自包含**                  | 每个头文件能独立编译。               | 用什么 include 什么                 | 依赖别的头文件间接 include   |
| ⭐⭐⭐⭐   | **Include 顺序统一**              | 工程结构更清晰。                     | 本文件→标准库→项目文件              | 随意 include                 |
| ⭐⭐⭐⭐   | **避免超长函数**                  | 超长函数难维护。                     | 每个函数 < 50 行左右                | 一个函数 300 行              |
| ⭐⭐⭐⭐   | **避免魔法数字（Magic Number）**  | 增强代码可读性。                     | `const int kMaxSize = 100;`         | `arr[100]`                   |
| ⭐⭐⭐⭐   | **常量统一命名**                  | 区分普通变量与常量。                 | `kMaxDepth`                         | `MAX` `max_depth2`           |
| ⭐⭐⭐⭐   | **适当添加注释**                  | 帮助理解复杂逻辑。                   | 注释“为什么这样做”                  | 注释“i++表示加1”             |
| ⭐⭐⭐    | **类内部顺序固定**                | 保持结构一致。                       | `public → protected → private`      | 顺序混乱                     |
| ⭐⭐⭐    | **每行代码不要过长**              | 提高阅读体验。                       | ≤100字符                            | 一行特别长                   |
| ⭐⭐⭐    | **一个文件只负责一个核心类/模块** | 降低耦合，提高组织性。               | `Graph` 单独文件                    | 多个结构混一起               |
| ⭐⭐⭐    | **使用 const 修饰不会修改的数据** | 提高安全性。                         | `void Print(const TreeNode* root)`  | `void Print(TreeNode* root)` |
| ⭐⭐⭐    | **优先使用引用而非裸指针**        | 更安全、更现代。                     | `void Swap(int& a, int& b)`         | `void Swap(int* a,int* b)`   |
| ⭐⭐⭐    | **减少全局变量**                  | 全局状态容易产生 Bug。               | 类成员管理状态                      | 到处使用全局变量             |
| ⭐⭐     | **避免复杂宏**                    | 宏容易产生隐蔽错误。                 | `const int kSize`                   | `#define SIZE 100`           |
| ⭐⭐     | **避免炫技式高级语法**            | 数据结构课程更强调清晰。             | 普通循环                            | 复杂模板元编程               |
| ⭐⭐     | **统一空格风格**                  | 保持视觉一致性。                     | `if (x == y)`                       | `if(x==y)`                   |
| ⭐⭐     | **适当使用 namespace**            | 防止大型项目冲突。                   | `namespace ds {}`                   | 所有内容都在全局             |

#### 系统架构

- ```
  VSCode插件
      ↓
  获取选中代码
      ↓
  AST解析（clang）
      ↓
  基础规范化（clang-format/clang-tidy）
      ↓
  LLM语义分析
      ↓
  语义重命名
      ↓
  教学解释生成
      ↓
  可视化友好IR生成
      ↓
  返回：
  - 规范代码
  - 修改原因
  - 数据结构标签
  - 可视化元信息
  ```

- ##### 第一层（规则级）

  AST 可解决：

  - 格式
  - 空格
  - include
  - brace
  - 命名风格

  ------

  ##### 第二层（语义级）

  LLM 解决：

  - 变量语义命名
  - 注释生成
  - 算法解释
  - 数据结构识别

  ------

  ##### 第三层（教学级）

  - 可视化辅助
  - 操作流程解释
  - 节点关系抽取

#### 明确限制

- 禁止修改算法逻辑
- 禁止改变时间复杂度
- 禁止改变数据结构行为
